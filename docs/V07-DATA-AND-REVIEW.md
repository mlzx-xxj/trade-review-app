# V0.7 OCR、洞察与数据安全

版本 0.7.0 / code 7 / com.tradereview.app；保留原记录与功能。

## 离线 OCR 与核实

使用 `com.google.mlkit:text-recognition-chinese:16.0.1` 打包版，而非 Play Services 下载版。[官方 Android 接入说明](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)。实际 AAR 含 Hani_ctc 与 Latn_ctc 模型；CI 检查最终 APK 模型资产。生产 Manifest 显式移除传递 INTERNET / ACCESS_NETWORK_STATE，CI 拒绝 INTERNET 或广泛存储权限。识别使用后台线程，不接云端 API。

系统 ACTION_OPEN_DOCUMENT 选择 JPEG/PNG/WebP，或从既有附件复制私有文件发起。沿用 V0.6 尺寸、类型、输入大小、容量、EXIF/GPS 清除、压缩私有 JPEG 策略。OCR 会话图片仅在私有 cache、原始文字仅在内存；取消清理，进程结束不恢复原始文字。显式保存的 OCR 草稿只含最多十三个可编辑字段和是否有已平仓依据，不存原 URI、识别全文或图片 Base64。恢复草稿会清除全部人工确认。缓存被系统清理时重新选图。

解析严格处理明确的中文/英文标签、日期、合约代码和规范数字。支持编号块、重复日期块与独立段落的多候选，每图至多二十条；不推断未知市场、币种、方向或风险参数。多次同字段不同值视为冲突，缺失/无效字段待核实。买卖价不自动映射开平仓角色。无明确已平仓/已实现依据、或含委托/持仓/浮盈/行情语义的候选仅能存草稿。复杂券商横向表格、无标签和模糊截图可能无法分条，需查看临时原文、裁剪清晰成交记录，或使用原快捷录入。

日期沿用 LocalDate/epochDay，未来日期不保存为成交。价格/数量使用 BigDecimal；净盈亏/手续费最多两位小数。归一后的字段必须逐项勾选，修改即取消该字段和已平仓确认；还要明确确认完整已平仓成交和最终净已实现盈亏，不能把毛盈亏当净盈亏。策略、实际仓位由用户选择；不把仓位当风险。OCR 手动净盈亏保持权威，不根据缺失乘数自动计算或扣除重复成本。

疑似重复按日期、市场、品种、方向、币种及精确净额比较，展示现有事实并要求显式仍新增；不会删除/合并旧交易。风险仍走 V0.5 引擎与确认指纹，保存时重新核对纪律和重复事实。新交易/可选图片元数据/OCR 草稿完成状态同一事务；先校验发布不可变图片，失败清理孤立文件。OCR 失败不写历史交易，保存不覆盖原快捷录入草稿。不确定信息仍可留在专用 OCR 草稿。

## 本地规则与口径

规则集中在 SmartInsights / PreflightRules，均可用纯 Kotlin 测试。观察窗口可选 7/14/30 天，对照此前等长自然日；报告使用当前周/月与上一完整周期，当前截至今天，天数可能不同。分类为纪律、风险、策略、情绪、习惯，可关闭，最低有效样本 3–100（默认 10）。结果按风险、重复错误等优先级排序，稳定规则 ID 去重；不足样本或未触发时显示暂无足够记录。洞察不永久存成财务结果。

- 重复错误：按稳定 ID/同市场品种统计，至少两笔；未标记不等于无错误。改善最多仅在两期均足够、次数及占比均下降时按次数降幅选择。
- 计划外：只用明确计划内外作分母，未知单列；两期足够且增加至少 10 个百分点。
- 风险：使用原不可变检查快照，可执行检查作分母，同笔多违规计一笔，未知不当作遵守；重复至少两笔，前期足够才判断次数变化。
- 复盘完成率：已复盘/全部交易，两期足够且下降至少 10 个百分点。
- 策略：同策略同币种，胜率含持平分母；变化至少 20 个百分点，或两期有效初始风险样本均足够且平均 R 差至少 0.5R。无风险不计 0R，不混合币种净额/R。
- 情绪：至少最低样本且亏损占比至少 60%，同时显示同期同币种基准；只描述共现，不宣称因果。
- 连续亏损：沿用交易日期、同日数据库 ID 排序，至少三笔；比较最长亏损段覆盖自然日内的全部交易频次与本期其余自然日。无精确成交时序，不把记录顺序当成真实秒级成交时间。
- 目标：使用自身周/月有效期和实际有效分母，达到最低样本、未达阈值且比上周期未改善时展示；文字目标不自动打分。计划内外表现卡是本期两组同币种净额对照，子组低样本提示，不误称前期对照。

每张卡展示时间/对照/样本/公式/检查建议，可展开依据并查看涉及真实交易；记录被删或改后派生结果随事实更新。建议是检查行为，不给具体证券/期货买卖指令或盈利预测。

## 盘前检查与迁移备份

盘前使用同一个日志日期，从严格早于该日的历史错误/违规、个人规则、生效目标与昨日有活动但未保存复盘生成提醒；不凭无活动日期虚构漏复盘。不自动保存 planSaved 或改写目标/交易。勾选只代表用户已检查，不代表交易事实遵守。手动项目可添加和归档，已检查历史保存当时文字/来源；关闭自动提醒不清除已保存历史。每条每日稳定 itemKey 唯一，避免重复项目；历史引用删除后保留检查事实。

Room v7 正式 `MIGRATION_6_7` 只 CREATE 四表：smart_settings、preflight_items、preflight_checks、ocr_drafts。原十二表、recordKey、净盈亏、专业/R/风险和附件完全保留，应用注册 v1→v7 全链，无 destructive migration。新安装默认设置与旧安装新增表为空时的默认值一致。

JSON schemaVersion 6、新 counts 和严格字段/类型/数量/稳定标识校验覆盖十六表，兼容 V0.2–V0.6 格式 1–5（含旧 ART 摘要布局）。JSON 仍明确 structured-data-only，不含图片；完整图片需 ZIP。ZIP 容器格式仍为 1、data.json 升级为 schema 6，manifest.json 与 images/ID-SHA.jpg 路径及逐文件 SHA/CRC、类型/尺寸、安全限额保持 V0.6：ZIP 256 MiB、解压 512 MiB、单图 4 MiB、JSON 16 MiB、manifest 4 MiB、10002 文件。新手动项目和 OCR 草稿各至多 100、检查历史至多 10000。原图政策和证据上限不变。

预览显示新增数量并二次确认；覆盖恢复完整替换十六表，合并稳定 ID/日期-itemKey 去重、冲突保留本地名称/归档/勾选/洞察设置，整体超限拒绝。预览过后任何新状态变化都使确认失效。文件先校验/同步发布，再单 Room 事务，失败回滚/清理，无丢图引用；原 ZIP 攻击防护与恢复回归保留。CSV 沿用全部交易/专业列，OCR 新确认交易自然纳入。备份是明文，SHA 是完整性校验而非身份认证；新版数据库/备份不支持旧 App 降级。

## 签名与限制

保留 V0.3 原证书 pin，不生成/读取/覆盖长期私钥。Secrets 名称查询返回 403；最终实际配置和证书以 Actions / SIGNING.txt / 独立 apksigner 为准。未完整配置则交付明确临时 Debug 包，不能保证覆盖固定包、其他临时包或未来升级。所有者在仓库 Settings → Secrets and variables → Actions，用既有 V0.3 keystore 配置 TRADE_REVIEW_KEYSTORE_BASE64、TRADE_REVIEW_KEYSTORE_PASSWORD、TRADE_REVIEW_KEY_ALIAS、TRADE_REVIEW_KEY_PASSWORD；Variables 配置 TRADE_REVIEW_UPGRADE_CERT_SHA256 为 docs/V03-CERTIFICATE-SHA256.txt 的公开 pin。不得在聊天/PR/日志提交私密材料；具体安全步骤沿用 V05-CALCULATIONS-AND-UPGRADES.md。

仍需真机验证首次飞行模式 OCR、厂家选择器、低内存/缓存清理、深色与键盘、同签名升级与大图库，见 V07-PHONE-ACCEPTANCE.md。模拟器合成图片验证不是对所有券商截图的识别准确率保证。保留压缩副本而非原照片字节，未知字段需人工核实。检查/目标历史可追溯，但派生洞察随着补录或修改更新。

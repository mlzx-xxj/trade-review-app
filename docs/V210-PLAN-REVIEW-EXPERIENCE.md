## 实际自动化与数据核对

生产MainActivity在一次性模拟器运行；启动前断言 `ro.kernel.qemu=1`。仅预置空账本和一条明确标注的合成策略。7笔成交、2条同日计划、3条真实周期复盘、期初配置和4条资金流水全部通过页面填写保存。系统日期选择器固定计划为2026-10-16，复盘/流水为2026-10-17；股票买入16日、卖出17日用于核对既有非同日卖出限制，不修改设备时间。日期为合成样本，不代表周末真实开市，也不扩展或改变已有T+1校验口径。

独立Python Decimal校验器从真实导出的账本核对下表，并逐项比较编辑前后的成交、开仓批次、匹配、周期、风险、规则及审计数据。前后新建UUID只在比较时规范映射，保留金额、字段及关联，原始JSON不改写。

| 合成样本 | 原始事实及核对结果 |
|---|---|
| 股票603999 | 1000股@10买入，费用1.00；1000股@11卖出，费用6.60；完全平仓，净盈亏992.40，累计费用7.60 |
| 螺纹钢rb2701 | 买开2@3500、加仓3@3510、卖平4@3490，费用7.01/10.54/13.97；FIFO先2后2，剩1手；原始净盈亏-628.006666666667，显示-628.01；剩余参考保证金2457.00 |
| 铁矿石i2701 | 买开2@800、平1@810，剩1手；费用、净盈亏和保证金保持null/待估算。匹配毛盈亏1000未冒充可用净盈亏 |
| 计划 | 同日两条不同ID；股票计划入场9.5/止盈12/止损9/自选策略；增加三关键价位后删除中间一项，最终支撑9、观察10.5；长文字编辑不生成成交 |
| 复盘 | 持有中、已平仓和费用待估算三个真实周期；长复盘保存并更正同一ID，记录止盈3600、止损3400及支撑3480；交易事实逐项不变 |
| 股票账户 | 期初10000且人工确认历史完整；入金1000更正1200、出金200。参考现金10000+1200-200+11000-10000-7.60=11992.40；配置前保持待估算 |
| 期货账户 | 可选期初20000、入金3000/出金500，净流入2500；含未知费用品种时总费用、净盈亏及参考保证金不伪装成零，不推算真实可用资金 |

空代码计划与0元流水被真实界面拒绝；取消后数据不变。每组由外部runner强制停止，再用不同PID重启；从页面重开长计划及复盘价位，并对整个保存账本做严格相等检查。

公共提示修复：原有字符串effect可能在同一帧内null→相同文本被合并后不再重启，已在旧TradeEntryExperience和新复盘路径观察超时。显示改为稳定循环，每次自然结束后重新等待下一条非空提示，使用compareAndSet避免清空不同的新消息；未改动ViewModel、数据库或任何金额。新增真实MainActivity回归在自然清空瞬间重发相同文本，断言再次显示、自然结束且账本不变。修复后的[API35专项39071757484](https://github.com/mlzx-xxj/trade-review-app/actions/runs/39071757484)实际完成17次instrumentation（1反馈、8计划/复盘/账户、8保留首页统计），原始反馈日志及归档/文件哈希保存在[专项来源](v210-plan-review-ui/diagnostics/focused-feedback-source.json)；不将专项冒充全量CI。

资金流水旋转恢复：基线有 **8/8** 组丢失编辑目标，测试实际取消该未保存窗口、重新打开原记录再更正，未用数据库补写绕过。新版所有组保留同一编辑目标，保存后仍为原ID、共4条流水；这是UI状态恢复修复，未更改流水计算和数据模型。

## 剩余限制与手机验收

窄屏大字体下账户较下方的参考数据需滚动查看；自动定位滚动命令数不等于用户滑动次数。没有用户手机实测；自动化能证明界面可操作、布局和数据状态，不能代替单手手感、个人审美和TalkBack完整体验。长表单和横屏需要滚动；图表、首页、成交录入及持仓未在本轮重新设计。没有制作正式V2.1覆盖升级包。

所有者可在隔离RC及合成数据中逐项确认，以下没有自动标为通过：

1. 浅/深主题查看计划、持有中/已平仓复盘及双账户，确认文字、信息密度与红盈绿亏符合习惯。
2. 创建两条同日计划，写长文、增加三关键价位再删除一项；取消一次，然后保存并重新打开。
3. 对真实界面成交形成的持仓写复盘，核对成交事实只读；对待估算品种确认没有显示虚假零净盈亏。
4. 开启键盘、大字体及旋转屏幕，检查取消/保存和文字编辑；试用TalkBack朗读与单手点击。
5. 记录入/出金，更正原流水时旋转，再保存，确认更正原流水且总条数没有增加。
6. 关闭并重开RC，核对内容仍在。正式App升级和真实数据恢复应另行验收，本轮没有操作手机数据。

本轮完成后停留在PR审核，不自动合并或发布，也不开始第三批。

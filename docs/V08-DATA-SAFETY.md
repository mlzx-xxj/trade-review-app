# V0.8 数据可靠性审查

应用 0.8.0/code 8，数据库仍 Room v7、JSON schema 6、ZIP 容器 1。新增的是查询、缓存与派生结果的范围信息，没有增加持久化表/列或用户设置，因此不强行升级数据库/备份版本。

## 稳定标识与关联

- trades 的 recordKey 唯一索引仍是跨备份的稳定交易标识；SQLite id 仅本机行号。专业信息与风险快照仍在原交易的 TEXT 字段，权威净盈亏与 recordKey 不重写。
- 附件以稳定 ID 和 recordKey 外键关联，ON DELETE CASCADE 与已有 recordKey 索引保留。新增单笔查找/计数、ID 查找使用这些已有索引，不新增索引或弱化核验；完整导出及孤立文件清理仍需全量引用。
- 删除前在同一事务比较完整原记录，防止覆盖恢复复用行号后，旧确认误删另一笔交易。失效确认要求重新打开；未删除时原截图也保留。
- 快捷草稿、OCR 草稿规则保持不变；编辑草稿通过原稳定标识和本机行号校验，去重合并恢复仍重新映射本机行号。未知价格/风险不填 0，手动权威净额保持原值。
- 标签 ID 与种类不改，隐藏/改名保留关联。检查历史保存当时文字与来源；被删除的交易/归档目标引用是刻意保留的历史快照，不当作当前事实或数据库外键。附件文件引用必须真实存在且摘要正确，不能按这种快照规则放宽。

## 备份、预览、事务与取消

正式 v1→v7 全链及旧 schema 文件保留，无 destructive migration。旧 V0.2–V0.7 受支持 JSON 格式 1–6 仍使用原规范化摘要和严校验；ZIP 1 兼容内部数据格式 5/6。JSON 明确仅结构化数据；有图片必须用完整 ZIP。

预览基于十六表事务快照；记录、规则、标签、设置、草稿或检查状态在确认前变化即失效，必须重新预览。覆盖/合并仍要求二次确认。合并按稳定 ID/日期项目键，冲突保留本地；清单键使用集合查找，保持原顺序与去重/限额语义。

新故障测试发现，Room 中连续同步 DAO 调用可能在外层任务已取消时继续并完整提交。恢复现在捕获调用方 CoroutineContext，在事务开始及提交前显式检查取消；SQL 调用中途取消则在提交前抛出并回滚十六表。取消发生在已提交之后不能撤销已经完成的事务；重启应看到完整提交，而不是半份数据。SQLite 事务与图片不可变文件发布顺序保持不变。

完整 ZIP 先校验并 fsync 发布文件再提交引用，失败/取消清理新孤立文件、保留原引用文件。预览读入在协程结果交付失败时释放自己持有的临时目录；ViewModel 销毁等待在途 IO/回滚结束再清理预览目录，避免提前删源图。进程终止的未引用文件和 .work 在启动时清理，不清理仍被数据库引用的图片。

保留单图 4 MiB、ZIP 256 MiB、解压 512 MiB、JSON 16 MiB、manifest 4 MiB、10002 文件，以及白名单路径、重复名、CRC/SHA、中央目录一致性、UTF-8、类型、尺寸和 GPS 校验。SHA 是完整性核验，不是加密或身份认证；备份仍是明文，不支持旧 App 降级读取新版数据库。

## 缓存与显示一致性

缩略图解码缓存至多 8 MiB，仅缓存不超过 512 边长的图；大图不保留在该缓存，内存压力释放缓存。命中也重新验证文件存在、长度及 SHA，同大小/同时间戳的损坏不能藏在缓存后。图片边界与记录尺寸相符才显示。缓存清理和在途加载通过代际/短内存锁协调，避免清理后旧请求回填；不 recycle 仍被界面/绘制系统持有的像素。缓存是派生状态，不入 Room 或备份。

Room 查询与后台统计独立刷新。派生报告记录计算时的交易/日志/币种/筛选范围，仅匹配当前范围时显示；等待新结果期间显示加载，阻止旧 CNY 金额在新 USD 标题下出现。此修复不改变胜率、平均 R、回撤或净额公式。

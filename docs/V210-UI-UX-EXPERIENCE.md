## 已发现问题与修正

1. 基线持仓主要是连续文字。360dp/1.0 字体的股票卡片 200dp、期货 208dp；320dp/1.3 字体分别达到 300dp、247dp。卡片没有突出剩余数量，也没有在摘要显示已实现净盈亏。
2. 基线 320dp 大字体加实际 IME 时，费用卡片占用较多高度，价格与数量框只露出一部分；保存按钮仍可用。新版将费率结果拆成并排的标签和值，并精简可视保证金标题。
3. 统一完整的 Material 表面颜色，避免原来的默认紫色容器与蓝色主色混用。详见设计规范的浅／深配色与实算对比度。
4. 第一轮云端编译发现新增测试使用了未导入的 DpRect 宽高扩展。已改用左右／上下边界差，保留 48dp 断言。
5. 大金额压力样本的初版手算预期有误。用独立 Decimal 复算 `123456.78 × 123456 × 0.0001`，按分 HALF_UP 为 `1,524,148.02`；只修正测试预期，不改生产费用算法。
6. 新版第一轮完整 [CI 38901009552](https://github.com/mlzx-xxj/trade-review-app/actions/runs/38901009552) 编译、241 JVM 和 Lint 成功，但 API 29 为 136 项中 3 失败、API 35 为 136 项中 2 失败，均无跳过。失败产物已下载核对 SHA 并保留。原统计测试仍直接点击已移到列表尾部的兼容档案入口，现改为先实际滚动再点击；财务断言未删。压力测试发现数量文字溢出，现使用实际行宽并保留测量余量，同时记录 TextLayoutResult。API 29 可选字段展开加入有界的节点等待，保留物理点击、可见性与超时失败截图，不重试或吞错。修复结果尚待新一轮完整 CI。
7. 代码审查还发现保存事件在重建时可能再次强制跳到历史成交。现将已处理的保存 ID 作为可恢复界面状态，只对新保存切页；增加旋转／重建后仍选中持仓的精确断言，不涉及账本或数据库。

## 发布与数据边界

本轮是界面 PR，不创建 V2.1 对外安装候选，不改变现有 2.0.0/code22、正式包名或 v2.0.0 Release。CI 沿用独立 `.rc.v200` 构建作为自动安装验证产物，其临时签名不代表永久签名缺失，也不能代替正式同证书升级验证。

Room 仍 v9，JSON 仍 8，ZIP 仍 1；没有 Migration、财务计算、历史数据重写或备份格式修改。下一次真正发布安装候选时必须递增 versionCode，并保留永久证书。PR 不接触签名 Secrets，不自动合并、不发布 Stable。

## 等待用户手机确认

自动化不代表真人体验，也没有执行用户手机安装或升级。后续取得版本号递增的可信候选后，建议在不删除现有数据的前提下逐项检查：

- 单手打开交易页并录入股票，价格／数量切换、数字键盘和底部保存是否顺手。
- 用常用列表选择期货合约，检查费用和保证金是否易于识别。
- 从持仓卡片辨认数量、方向和已实现净盈亏，点击后能否找到日期、止盈止损及分批成交。
- 切换系统深色及大字体；检查自己手机的输入法、导航手势、横屏是否遮挡操作。
- 关闭并重新打开，核对同一笔成交；备份恢复仅在隔离测试环境使用合成数据，不覆盖真实账本试验。
- 判断红盈绿亏是否舒适、卡片是否过密或过疏。这些审美与触感偏好仍须由所有者决定。
